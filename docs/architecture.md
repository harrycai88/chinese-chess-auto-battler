# 架构与实现

> 这份文档描述 **v0.1 实际落地的代码**，而不是远期规划。  
> 设计意图与规则语义仍以根目录 `README.md` 为准。

## 1. 依赖方向

```text
src/ui  ──┐
          ├──> src/engine
src/render ┘
```

- `src/engine`：纯 TypeScript，零 DOM、零 Vue、零 Canvas、零 Web Audio、零系统时钟。
- `src/render`：只读引擎状态与事件，绝不回写。Canvas 2D 绘制 + Web Audio 合成。
- `src/ui`：Vue 3 控制台与观战 HUD，只通过 `BattleEngine` 的公开接口推进对局。

## 3. 一帧的生命周期

```text
requestAnimationFrame
  └─ 累积真实时间 dt * 倍速
       └─ while accumulator >= 1/60: engine.step()
            ├─ 时钟 / 加时
            ├─ 每 0.125s 生成双方只读快照
            ├─ 跑策略 → 校验白名单意图 → 写入单位
            ├─ 计时器 / 兵种机制 / 攻击 / 位移 / 分离
            ├─ 弹体 / 回血 / 复活 / 加时流血
            └─ 胜负判定
       └─ drainEvents() → 渲染特效 / 音频 / 战报
```

- 引擎只按固定步长推进，与渲染帧率、暂停、倍速、标签页是否可见无关。
- 渲染层对位置做平滑插值；表现计时（攻击后摇、受击闪白）由引擎提供，保证可复现。

## 4. 确定性

- 所有随机来自 `Rng`（种子初始化），引擎内不出现 `Math.random` / `Date.now`。
- 单位处理顺序在开局按种子洗牌，避免红方永远先手。
- 伤害有 ±10% 的可复现浮动；开局有 ±0.035 格扰动；复活有 ±0.08 格散点。
- 遍历顺序固定：按 `turnOrder`、按数组下标，不依赖对象键顺序。
- 暂停、倍速、关闭特效、静音，都不改变对局结果。
- 同种子 + 同配置 + 同策略 → 完全一致的结果（见 `tests/engine.test.ts` 的确定性与黄金对局用例）。

## 5. 表现层

- **Canvas 2D**：木质棋盘、外扩木面、玉石棋子、底座圈、基地、血条、弹体、粒子、伤害数字。
- **棋子精灵预渲染**：每个阵营 × 兵种生成一次 160×160 精灵，绘制时缩放，避免每帧创建径向渐变。
- **特效**：挥砍弧、锥形霰弹、炮口焰、爆炸、烟尘、跃击残影、传送光柱、复活光柱、回血粒子、基地焦痕与残烟。
- **音频**：全部由振荡器 + 噪声缓冲实时合成；按事件类型节流，基地告破 / 加时 / 终局优先穿透。
- **可降级**：`伤害数字 / 战场特效 / 意图线 / 音效` 四个开关都在观战 HUD 中；关掉后判定不变。

## 6. UI

- **战前**：双方策略卡（可镜像 / 对调）、局时、初始倍速、种子、画面开关、四项数值微调；设置写入 `localStorage`。
- **观战**：顶部基地血量与计时；左侧双方策略、兵力编成、伤害/攻城；中间战场；右侧单位档案与战报；底部事件摘要。
- **移动端**：侧栏收起为「战报」抽屉，顶栏保留比分、计时、暂停与画面设置；倍速在画面设置中调整。
- **结算**：胜方、结束原因、双方基地、总伤害、种子；可再战（换种子）、返回配置或留在战场查看。

## 7. 与 README 的设计差异（v0.1）

| 设计稿 | v0.1 实现 | 原因 |
|:--|:--|:--|
| PixiJS（Canvas 2D 兜底） | Canvas 2D | 规则与表现解耦；2D 手绘足够承载当前规模，且没有额外运行时依赖 |
| 浏览器内 Web Worker 跑引擎 | 主线程固定步长 | 30 单位 / 8Hz 决策在实测中稳定 160+ fps；Worker 作为路线图 |
| 外部策略文件夹加载与隔离 | 内置策略注册表 | 先把规则、表现、两套策略打磨完整；协议已抽成 `Tactic` 接口 |
| 回放链接 / 对阵矩阵 | 种子可复现 + 无头批量仿真 | 初版保留最小复现能力，UI 侧暂不做分享链接 |

## 8. 扩展点

- 新增兵种：`config.ts` 的 `units` + `battle.ts` 的机制分支 + `renderer.ts` 的精灵字符。
- 新增策略：实现 `Tactic`，在 `tactics/index.ts` 注册；只依赖快照与白名单意图。
- 新增表现：订阅事件流，不改引擎；所有特效都应可通过开关关闭。
- 新增模式：通过 `MatchOptions` 缩放数值；需要新规则的玩法应新增配置域，而不是在分支里写魔法数。
